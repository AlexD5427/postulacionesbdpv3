# Internacionalizacion · REGLA OBLIGATORIA

## 1. La regla

> **Todo texto que un usuario pueda leer en el frontend debe existir en los
> cuatro idiomas soportados. Sin excepciones.**

| Codigo | Idioma | Endonimo |
| --- | --- | --- |
| `es` | Espanol latinoamericano (idioma base) | Espanol (Latinoamerica) |
| `en` | Ingles | English |
| `qu` | Quechua | Runa simi |
| `ay` | Aymara | Aymar aru |

Esto aplica a **toda** la interfaz: portada, convocatorias, login, registro,
panel, evaluaciones, recursos, bolsa de talento, mensajes de error, avisos,
textos de accesibilidad, etiquetas `aria-label`, marcadores de posicion de
formularios, tooltips y textos de estados vacios.

Ninguna funcionalidad nueva se considera terminada si solo esta en espanol.

---

## 2. Como agregar un texto

### 2.1 Textos de interfaz

Viven en `lib/i18n/dictionaries.ts`, como pares clave/valor planos.

```ts
// 1. Agregar la clave al diccionario base (es)
const es = {
  'panel.tab.entrevistas': 'Entrevistas',
};

// 2. Agregarla en en, qu y ay
const en = { 'panel.tab.entrevistas': 'Interviews' };
const qu = { 'panel.tab.entrevistas': 'Tapukuykuna' };
const ay = { 'panel.tab.entrevistas': 'Jiskht\'awinaka' };
```

Uso en un componente cliente:

```tsx
const { t } = useI18n();
<h2>{t('panel.tab.entrevistas')}</h2>;
```

**Convencion de claves:** `dominio.subdominio.detalle` en minusculas
(`jobs.filter.city`, `a11y.readingGuide`, `panel.alerts.created`).

### 2.2 Textos que vienen de datos

Los datos (convocatorias, preguntas, recursos) usan el tipo `L<T>`, un objeto
localizable donde `es` es obligatorio:

```ts
titulo: {
  es: 'Analista Senior de Riesgo Crediticio',
  en: 'Senior Credit Risk Analyst',
  qu: 'Manu chanin qhawaq yachaq',
  ay: 'Manu chani uñakipir yatiri',
}
```

Se resuelve con `tl()`:

```tsx
const { tl } = useI18n();
<h3>{tl(conv.titulo)}</h3>;
```

## 3. Comportamiento de respaldo

Los diccionarios de `en`, `qu` y `ay` se construyen sobre `es`:

```ts
export const DICTIONARIES = {
  es,
  en: { ...es, ...en },
  qu: { ...es, ...qu },
  ay: { ...es, ...ay },
};
```

Consecuencia: **la interfaz nunca muestra una clave cruda**. Si falta una
traduccion, aparece el espanol. Esto es una red de seguridad, **no** una excusa
para no traducir.

`COVERAGE` y `TOTAL_KEYS` (exportados del mismo archivo) permiten medir la
cobertura real por idioma en revisiones y tableros de calidad.

## 4. Cobertura y revision

Estado al momento de esta version:

- `es`: 100% (idioma base, referencia de contenido).
- `en`: cobertura completa de la interfaz.
- `qu` y `ay`: **traduccion funcional** de la interfaz nuclear (navegacion,
  hero, convocatorias, panel, formularios, accesibilidad, errores).

> **Pendiente obligatorio:** validacion por hablantes nativos de quechua y
> aymara antes de publicar en produccion. Las traducciones actuales priorizan
> comprension funcional; algunos terminos financieros no tienen equivalente
> establecido y se resolvieron con perifrasis o prestamo del castellano
> (por ejemplo `correo electronico`, `banco`).
>
> Al recibir la validacion, actualizar los bloques `qu` y `ay` y registrar el
> cambio en `docs/CHANGELOG.md`.

## 5. Detalles tecnicos

- **Cambio de idioma:** boton dedicado en la cabecera y en el menu a pantalla
  completa (`components/LanguageSwitcher.tsx`). Cada opcion se muestra en su
  propio idioma. Tambien se puede cambiar desde la paleta de comandos
  (`Ctrl/Cmd + K`).
- **Persistencia:** la eleccion se guarda en `localStorage`. En la primera
  visita se detecta el idioma del navegador si coincide con uno soportado.
- **`<html lang>`** se actualiza en cada cambio (`es-BO`, `en-US`, `qu-BO`,
  `ay-BO`) para lectores de pantalla y buscadores.
- **Formatos:** fechas y moneda usan `Intl` con `es-BO` o `en-US`. Quechua y
  aymara no tienen datos garantizados en `Intl`, por lo que usan el formato
  numerico de `es-BO` conservando su idioma en la interfaz.
- **Lectura por voz:** si el motor del navegador no tiene voz nativa para
  quechua o aymara, se usa pronunciacion espanola y el panel lo advierte
  explicitamente (`a11y.ttsNoNativeVoice`).

## 6. Lista de verificacion antes de un PR

- [ ] Toda clave nueva existe en `es`, `en`, `qu` y `ay`.
- [ ] Ningun texto literal escrito directamente en JSX.
- [ ] `aria-label`, `title` y `placeholder` tambien traducidos.
- [ ] Datos nuevos usan `L<T>` con al menos `es`, `en` y, cuando sea texto
      visible clave, `qu` y `ay`.
- [ ] Probada la pantalla en los cuatro idiomas (los textos largos en ingles y
      quechua cambian el ancho: revisar que no se rompa el layout).
